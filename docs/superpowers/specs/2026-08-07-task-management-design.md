# 任务管理设计

## 目标

在工作台左侧的当前仓库任务列表中，为未在执行的任务提供与仓库卡一致的“更多”菜单。用户可重命名任务标题或永久删除任务及其历史运行记录；工作台新建任务表单不再要求单独填写标题。

## 交互

- 新建任务只保留“描述”和“轮次”字段。
- 服务端从描述的规范化文本生成默认标题：取前 32 个字符；若描述为空，使用“未命名任务”。
- 每个任务项右侧显示一个“更多”按钮，菜单位置与仓库卡的更多菜单一致，但与任务标题同一行、靠右显示。
- 菜单仅在该任务没有 `running` 或 `waiting_approval` 运行记录时显示。
- “重命名”打开与仓库重命名一致的对话框，预填当前标题。保存后只更新标题，不修改描述或运行历史。
- “删除”打开确认对话框，明确说明会永久删除任务及其运行、动作、反馈、上下文、审批和工具结果；仓库工作区文件不会被删除。
- 如果任务在菜单打开后开始运行，后端仍拒绝重命名和删除，以状态检查作为最终保护。

## 数据与接口

- `HarnessStorage.rename_task(task_id, title)` 更新 `task.title`。
- `HarnessStorage.delete_task(task_id)` 在单一 SQLite 事务中按依赖顺序删除该任务的运行关联数据和任务本身。
- `CoreService.rename_task(task_id, title)`、`CoreService.delete_task(task_id)` 负责验证任务存在且无活动运行。
- `POST /ui/tasks/{task_id}/rename` 接收 JSON `{ "title": "..." }` 并返回更新后的任务。
- `POST /ui/tasks/{task_id}/delete` 删除后以 `303` 返回工作台。

## 活动运行定义

只要任务任一运行记录的状态为 `running` 或 `waiting_approval`，该任务即为活动任务，不能重命名或删除。`pending`、`succeeded`、`failed`、`stopped` 不阻止管理操作。

## 验收标准

- 工作台 HTML 不再包含新建任务标题输入框。
- 通过 WebUI 创建任务时，标题从描述生成并截断至 32 个字符。
- 非活动任务在右侧展示更多菜单和重命名／删除对话框；活动任务不展示菜单。
- 后端拒绝活动任务的重命名与删除请求。
- 删除非活动任务会删除其所有关联运行数据和任务记录，但不删除仓库文件。
