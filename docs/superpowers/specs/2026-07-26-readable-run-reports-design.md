# 可读运行报告设计

## 目标

将面向用户的 Markdown 运行报告从原始 JSON 转换为中文、可快速浏览的审计摘要。网页的“报告”区域与“导出 MD”使用同一份报告内容；JSON 导出继续作为机器可读和完整审计数据。

## 范围

- 保留 `CoreService.export_report(..., fmt="markdown")` 与现有 JSON 导出接口。
- 将 Markdown 报告的字段按业务语义渲染：任务与运行概览、最终结论、已选上下文、动作轨迹、反馈、审批和技术明细。
- 仅在“审计原始数据”区域保留脱敏后的原始字段；网页可将该区域折叠。
- 不修改运行、存储或脱敏规则。

## 渲染规则

1. 报告开头显示任务标题、任务请求、运行状态、轮次和停止原因。
2. 从 `finish` 动作的 `summary` 参数提取并展示“最终结论”。
3. 上下文按文件列出路径、类型、选择原因和评分；省略内部 ID、仓库绝对路径与时间戳。
4. 动作按轮次展示动作名称、目标（文件、命令或其他参数）、护栏结果与执行结果摘要；不展示 JSON 字符串。
5. 反馈与审批各以状态、原因和处理结果呈现。
6. 完整脱敏原始数据位于报告结尾，供审计或排障使用。

## 数据流与兼容性

`ReportExporter` 接收既有报告 payload，先执行现有脱敏逻辑，再转换为 Markdown。网页继续调用 Markdown 导出，因此无需维护第二套字段映射。`to_json()` 不变。

## 验证

- 新增导出器测试，覆盖上下文、动作、最终结论、反馈与审批的可读渲染。
- 断言默认 Markdown 不将主体对象渲染为 JSON 代码块。
- 断言敏感值仍被脱敏，JSON 导出仍保留原有结构。
